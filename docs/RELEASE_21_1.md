# Sophyane 21.1 release notes

Sophyane 21.1 focuses on reliable end-to-end software delivery, especially complete browser products generated by cloud models.

## Highlights

### Verified browser delivery

Sophyane now supports the full path:

```text
semantic request
  → provider planning
  → isolated workspace
  → complete artifact generation
  → validation
  → HTTP verification
  → new-tab browser preview
```

A successful run reports the written file, byte size, HTTP verification result, artifact fingerprint and verified preview URL before opening the success menu.

### Semantic repair instead of blind continuation

A complete HTML document with a functional defect is not a truncated byte stream. Sophyane 21.1 distinguishes these cases:

- Structural incompleteness uses bounded continuation.
- Semantic failure uses a full-document replacement request.
- Repaired full HTML replaces the prior document rather than being appended outside `</html>`.

The Snake-game validator also recognizes common vector-based reverse-direction guards and queues at most one direction change per game tick.

### Live TUI repair precedence

The interactive TUI installs several wrappers after the main CLI starts. Earlier releases could accidentally replace the semantic repair prompt with a generic continuation prompt. Sophyane 21.1 reapplies semantic repair after the TUI recovery stack so it remains the final authority.

### Cloud response windows

Cloud models sometimes need more than 60 seconds to produce complete engineering artifacts. Defaults are now:

- Cloud providers: 120 seconds
- Local providers: 60 seconds
- Explicit caller timeout: unchanged and authoritative

Timed-out calls are not automatically duplicated.

### Safer success reporting

The success menu opens only when:

- The runtime result is positive.
- A real user-facing artifact exists.
- The artifact is new or changed.
- Browser products pass the relevant validation path.

On terminal validation failure, generic file writes, Python execution, browser opening and queued tool actions are blocked for that request. Rejected provider evidence remains available for debugging.

## Upgrade from an editable installation

```bash
cd ~/sophyane-repo
git checkout main
git pull origin main

VENV="$HOME/.venvs/sophyane21"
"$VENV/bin/python" -m pip install -e '.[dev]'
"$VENV/bin/python" -m pytest -q
```

Then verify:

```bash
"$VENV/bin/sophyane" --version
"$VENV/bin/sophyane-benchmark"
```
