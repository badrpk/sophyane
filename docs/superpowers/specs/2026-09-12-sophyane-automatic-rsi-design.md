# Sophyane bounded automatic RSI design

Approved architecture and automatic promotion policy, 2026-09-12.

## Preservation and execution contract

Continue from the current worktree, including all legitimate uncommitted Mode-6 changes. Never reset, discard, restore, clean, stash, revert, commit, push, alter remote branches, delete failing tests, mutate secrets, or change persistent provider configuration to satisfy tests. Test fixtures alone create commits in temporary repositories. Record initial file hashes and diff outside the repository. All verification uses `PYTHONPATH="$PWD/src" .venv-full/bin/python` (working repository Python if absent). No activation against the dirty development tree.

## Authority and scope

Central authority checks every source, candidate-test, executable, provider-policy, verification-policy, checkpoint, promotion, and rollback mutation. Only exact canonical `codex_cli` and `nifdu_browser` identities qualify as coding providers. Aliases, case variants, unknown names, local GGUF, and Gemini cannot acquire mutation authority. Local GGUF may read state, summarize recorded logs, classify recorded failures, monitor processes/tests/metrics, and perform non-source-mutating operations. It cannot produce automatically applied patches, execute modifying commands, approve or promote candidates, or change rollback/checkpoint state. The trusted deterministic controller owns transaction decisions; the writing LLM never approves its own output.

General Mode-6 remains `codex_cli -> nifdu_browser -> local_gguf`; capability-aware source mutation uses exactly `("codex_cli", "nifdu_browser")`, then `DEFERRED_NO_CODING_PROVIDER`. Preserve explicit Mode-4 selection, Mode-3 operations, global Gemini support, camera/vision, repository execution, and same-provider semantic repair. Add an explicit capability to Mode-6 routing with read-only compatibility default; source callers must declare mutation authority. RSI uses its dedicated router exclusively.

## Modules and records

Create `src/sophyane/rsi/`: `models.py` owns JSON-friendly typed records and states; `authority.py` canonical capabilities and hard denials; `weakness.py` structured evidence validation/detection; `baseline.py` reproducible Git identity and measurements; `candidate.py` isolated worktrees and constrained file replacement; `coding_provider.py` availability-aware proposal routing; `verification.py` fresh-process commands and gates; `benchmark.py` deterministic metric comparison; `promotion.py` immutable checkpoint and transaction; `rollback.py` recorded restoration; `journal.py` append-only audit; `controller.py` one bounded iteration; `__init__.py` package documentation. Additional `availability.py` owns external persistent observations independently of candidate code.

States: NO_ACTION, DETECTED, BASELINED, CANDIDATE_CREATED, RED_CONFIRMED, MODIFYING, VERIFYING, REJECTED, DEFERRED_NO_CODING_PROVIDER, PROMOTION_READY, PROMOTING, PROMOTED, ROLLED_BACK, VERIFIED_BASELINE, CANCELLED. Weakness records include id, description, evidence, baseline commit, metric, baseline value, required improvement, protected metric tolerances and verification commands. Baseline records include exact commit, repository/common-Git identity, worktree/clean reproducibility data, metrics, tests and authority configuration. Candidates include id, baseline, name, path, provider, source authority, optional candidate commit. Verification records include RED, GREEN, targeted, subsystem, full, static/diff, authority, isolation, benchmark, protected metrics and smoke. Decisions contain boolean, reasons and recorded evidence.

## External persistent quota cognizance

Initialize authoritative state before creating candidates. Resolve `$XDG_STATE_HOME/sophyane/provider_availability.json`, otherwise `~/.local/state/sophyane/provider_availability.json`, once in trusted host context. Explicit test injection is supported, but paths inside baseline/candidate worktrees are rejected. Candidate environment changes cannot redirect this resolved store. Read existing version-1 observations conservatively without modifying the legacy Mode-6 implementation. Persist canonical provider, observed_at, sanitized unavailable_reason, failure_class, retry_at, probe_after, independent cooldowns, last_success_at and last_probe_at. Never store credentials, cookies, tokens, prompts, or raw provider responses. Atomic replace, restrictive permissions and serialized updates prevent partial writes. Invalid state fails closed rather than silently enabling coding.

Each request reloads state using an injectable timezone-aware clock, expires elapsed cooldowns, considers Codex first and NIFDU second. Future retry_at or probe_after means skip without constructing/consuming a provider. Exactly at expiry Codex resumes first priority. Independent short-window/5-hour and weekly cooldowns all must expire. Independent provider health permits NIFDU during Codex cooldown, without making it sticky.

Recognize usage limit, quota, rate limit, credits, HTTP 429, 5-hour limit and weekly limit; recognize try again at/reset at/resets tomorrow at local clocks without tzdata, resolving timezone-less times in system local time. Untrustworthy reset descriptions use a bounded probe_after, never invented exact retry_at. Semantic quota output means failure even with outer exit 0, including `ChatGPT usage limit reached` plus `Native Sophyane execution failed safely`.

Fail over only on executable/session/browser/CDP absence, connection/timeout/temporary availability, quota, HTTP 429/500/502/503/504 and explicitly recognized equivalents. Inspect entire cause/context chains: cancellation, KeyboardInterrupt, TypeError, AssertionError, programming/schema/malformed-action errors, authority/isolation violations and deterministic test failures are terminal even when wrapped in transport wording. Both unavailable means deferred; local/Gemini are never constructed.

## Baseline, isolation and RED

Require clean tracked and untracked baseline state, an exact commit matching the weakness, passing baseline regression evidence and measured baseline metrics. An arbitrary dirty tree is never an immutable baseline. Create exactly one detached Git worktree from that commit under a separate managed candidate directory. Providers receive candidate context through read-only proposal adapters; executable file application validates all paths before writing, rejects traversal, symlinks, hardlinks and Git metadata, and uses a host-owned editable-path allowlist excluding authority/verification/checkpoint policy. Providers cannot alter authoritative external state or verification commands. Reject/cleanup operates only on the recorded candidate worktree, never baseline.

RED is a host-selected command with exit code, expected failure marker, output and digest. It must fail for the objective, not an already-passing test, syntax/import setup error or unrelated suite noise. The same immutable command must become GREEN. New candidate tests, when requested, are separately authority-checked; the first version accepts a pre-existing failing weakness command so RED does not depend on an LLM assertion.

## Verification and metrics

Run trusted argv commands without shell, in fresh processes with candidate `src` first in PYTHONPATH, no bytecode or pytest cache, bounded timeouts and cancellation checks. All mandatory gates veto promotion independently: RED-to-GREEN, targeted, subsystem, full, git diff --check, authority, isolation, benchmark and protected metrics. LLM text cannot override them. Record full command, result and output digest. Verification commands and metrics are supplied by the trusted host, not rewritten by candidate output.

Benchmark A and B with metric records, never a universal intelligence score. A direction per metric supports higher/lower better. Require finite values, target delta >= strictly positive required improvement, and all protected metrics within absolute tolerated degradation. Missing/NaN measurements reject. Passing tests does not excuse equal/worse target or protected regression.

## Transaction, rollback and journal

Only deterministic passing evidence yields PROMOTION_READY. Freeze candidate tree into a local Git object/commit using plumbing at runtime, without committing the developer worktree or touching remotes. Before mutation, persist an exclusive immutable JSON checkpoint containing iteration/parent, A/B commit, weakness, RED/GREEN, all tests, A/B metrics, decision, provider/failovers and timezone-aware timestamp; retain Git references to checkpoint commits. Acquire a repository transaction lock and compare baseline HEAD and cleanliness again. Use Git's two-tree read-tree transition and compare-and-swap ref update to promote only the exact measured candidate. Never use reset --hard. Refuse concurrent/stale/dirty state rather than overwriting it.

After promotion run host-owned smoke commands in a fresh process. Failure automatically restores exact A tree/HEAD from the persisted checkpoint, records ROLLED_BACK and retains diagnostics. A crash-recovery entry point reads the checkpoint and conservatively restores A for unfinished transactions. A successful smoke records VERIFIED_BASELINE; only then may a caller start another iteration. A cancellation before promotion aborts; cancellation after transition triggers restoration of the in-flight transaction, never a new promotion.

JSONL journal uses stable UUID iteration ids, parent iteration, baseline/candidate commits, weakness, coding provider, failovers, RED/GREEN, targeted/full results, A/B metrics, promotion/rollback results and timestamps. Append/fsync events, reject duplicate checkpoint overwrite, and retain failure evidence. Local GGUF cannot write audit/checkpoint state through the authority API.

## Bounds and validation

`Controller.run_once` supports one candidate, a positive maximum repair-round count and lifecycle deadline, and cooperative cancellation at every destructive boundary. No concurrent racing or uncontrolled recursion. Missing measurable weakness returns NO_ACTION. Runtime code is tested only against temporary Git repositories and fake text providers; no live provider requests or user quota/config writes during implementation.

Tests under `tests/rsi/`: authority; candidate isolation; provider failover and fake-clock persistent availability; RED gate; verification vetoes; benchmark comparisons; automatic promotion; automatic rollback; journal; end-to-end cycle. Mandatory E2E cases: known weakness A -> real RED -> qualified repair B -> all GREEN/metrics -> automatic promotion -> fresh smoke -> VERIFIED_BASELINE; smoke failure restores exact A; Codex quota invokes NIFDU; both unavailable defers despite available Local; local mutation attack causes no writes. Also cover exact retry boundaries, independent windows/providers, process restart, candidate state override, cancellation, repair exhaustion and stale transactions.

Run focused RSI, the eleven requested Mode-6/conversation/discovery/camera/voice/fallback files, relevant Codex/NIFDU/Local suites, then one full pytest suite. Do not treat interrupted full runs as completion. Record every exact command/exit/pass/fail/skip and RED expected failures. Run diff check/status/stat/name-only, static provider-order and Local-read-only proof, forbidden-command review, and preservation hashes. Final report uses the user's exact nineteen section labels and honestly lists remaining issues. Leave all work uncommitted and unpushed.

## Reviewed execution isolation and host availability

Git isolation alone cannot prevent imported candidate code from writing host state. Therefore production verification, baseline measurements and post-promotion smoke require Bubblewrap with the host filesystem mounted read-only, isolated namespaces, a private temporary filesystem, and a reduced environment. There is no unrestricted-execution fallback. If Bubblewrap or required kernel namespaces are unavailable, automatic RSI refuses execution before provider invocation or promotion. This Android host has no Bubblewrap, user-namespace isolation is unavailable, and its Landlock syscall probe returns ENOSYS. Controller E2E tests explicitly substitute a trusted authored-fixture runner; they prove transaction orchestration, not OS sandbox availability. A separate real-sandbox test is skipped when Bubblewrap is absent, and a fail-closed test remains mandatory. Live activation on this host is blocked until an enforcing sandbox exists.

Verification snapshots candidate file bytes before GREEN and rejects any change during regression/benchmark. RED requires the expected assertion diagnostic itself and rejects multi-failure suite noise. Host policy cannot list its own verification scripts as editable. A repository lifecycle lock prevents parallel iterations; persisted PROMOTING/PROMOTED records are recovered from their immutable checkpoints before another iteration starts. Rollback refuses unrelated human working-tree/index/untracked changes and never reports exact restoration without clean A verification. This refusal is a preservation boundary; read-only smoke prevents transaction-owned file pollution.
